# دانشنامه

**جایگاه در HBI:** دانشنامه یکی از مسیرهای سازمان‌دهی و نمایش اطلاعات است و جایگزین یا مخزن موازی ProductKnowledge نیست. معماری معتبر HBI در [تصمیم سه‌بخشی HBI](../../03_decision_log/HBI-PO-DEC-THREE-PART-001.md) تعریف شده است.

ProductKnowledge بانک واحد اطلاعات معتبر محصولات است. اطلاعات هر محصول طبق استانداردها و معیارهای پذیرش تعیین‌شده توسط مقصودی گردآوری و بررسی می‌شود و پس از تأیید مقصودی آماده ورود به ProductKnowledge است. دانشنامه می‌تواند محتوای تأییدشده را به‌شکل قابل فهم و قابل دسترس سازمان‌دهی کند؛ اما نباید برای همان اطلاعات، بانک، فرایند تأیید یا مرحله QA جداگانه بسازد.

## مرزهای اختیار و منابع

- معماری و مسیر ورود اطلاعات محصول: [HBI-PO-DEC-THREE-PART-001](../../03_decision_log/HBI-PO-DEC-THREE-PART-001.md).
- تصمیم‌ها، مجوزها و Gateهای ویژگی‌ها و توانمندی‌های محصولات و سیاست‌های مرتبط هوم‌پیج: [Issue #406](https://github.com/vahidmaghsoudi2/hbi/issues/406).
- شواهد فنی و پژوهش Product Knowledge: [PR #411](https://github.com/vahidmaghsoudi2/hbi/pull/411) و مراجع مرتبط آن.
- فهرست ProductKnowledge: [KB_INDEX](../../05_knowledge_base/KB_INDEX.md).
- منابع و شواهد پشتیبان اطلاعات محصول: [EVIDENCE_INDEX](../../07_evidence/EVIDENCE_INDEX.md).
- این پوشه: ساختار دانشنامه، ناوبری و محتوای قابل ارائه؛ نه یک بانک محصول موازی.

**منوی واقعی برنامه:** frontend/src/pages/NewHomePage.tsx (کارت دانشنامه). تغییر فایل‌های مستنداتی به‌تنهایی UI تولید را عوض نمی‌کند.

## قواعد ثبت و بازبینی

1. محتوای مربوط به محصول باید با اطلاعات تأییدشده ProductKnowledge سازگار باشد.
2. منبع اطلاعات مهم و محدودیت‌های آن را در صورت نیاز حفظ کنید تا امکان بررسی صحت وجود داشته باشد.
3. ادعای سازنده را به‌عنوان ادعای سازنده معرفی کنید؛ آن را بدون پشتوانه به حقیقت علمی مستقل تبدیل نکنید.
4. اطلاعات ناقص یا نامطمئن را قطعی جلوه ندهید. ابهام مهم باید پیش از پذیرش محصول طبق معیارهای مقصودی بررسی شود.
5. تأیید مقصودی پایان فرایند پذیرش اطلاعات محصول است؛ دانشنامه نباید تأییدیه یا سد جداگانه‌ای پس از آن ایجاد کند.
6. دانشنامه جایگزین Product Master، موجودی، وضعیت چرخه عمر محصول یا قواعد عملیاتی موجود نیست.

## ساختار داخلی دانش پوست

مسیر ناوبری مصوب و جاری در هوم‌پیج:

دانشنامه → دانش پوست → (ویژگی محصولات پوستی | مشکلات پوستی)

- **ویژگی محصولات پوستی:** نمای read-only موجود و [فهرست پژوهش P1–P7](./skin/PRODUCTS.md).
- **مشکلات پوستی:** پیوند به [Workspace Index بانک مرجع P01–P61](../../product-intake-knowledge-registry/SKIN_PROBLEM_BANK_WORKSPACE_INDEX.md).
- این دو مقصد از نظر دامنه و مرجع تخصصی مستقل‌اند؛ هیچ‌یک داده‌های دیگری را کپی نمی‌کند. ارتباط مستند محصول/مشکل از ProductProblemLink موجود پیروی می‌کند.
- این ساختار ناوبری، به معنی ادغام دو بانک تخصصی یا افزودن نمایش زندهٔ روابط در UI نیست.

## قواعد نگهداری

1. تصمیم معماری جاری در [HBI-PO-DEC-THREE-PART-001](../../03_decision_log/HBI-PO-DEC-THREE-PART-001.md) ثبت شده است؛ سند CKER صرفاً سابقهٔ تصمیم superseded است.
2. تصمیم‌ها و مجوزهای حوزهٔ محصول در Issue #406 باقی می‌مانند.
3. زیرمنوهای اصلی دانشنامه حذف نمی‌شوند؛ فقط محتوای داخل آن‌ها ویرایش می‌شود.
4. محصول داخل دانش پوست در skin/PRODUCTS.md ثبت می‌شود؛ این ثبت به‌تنهایی Product Master یا ProductKnowledge عملیاتی ایجاد/تغییر نمی‌دهد.
5. ادعای پزشکی یا تکمیل بانک محصول بدون پشتوانه و مجوز مربوط ثبت نشود.
6. Issue یا PR موازی برای همین ساختار نسازید مگر مالک محصول بخواهد.
