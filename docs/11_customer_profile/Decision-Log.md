# Decision Log — واحد پروفایل مشتری

**روش:** در نبود پاسخ لحظه‌ای PO، تصمیم با دیدگاه «مدیر گالری آرایشی‌بهداشتی — مشتری‌مدار، منطقی، پرفروش» + نقش فنی Grok1.

| # | سؤال | تصمیم v1 | دلیل گالری |
|---|------|----------|------------|
| 1 | name vs first/last | همان فیلد `name` | فروشنده «نام مشتری» می‌گوید؛ شکستن نام ارزش Pilot ندارد |
| 2 | Guest ID | `CUST_GUEST_YYYYMMDDHHMMSS` | بدون موبایل هم فروش و مشاوره راه بیفتد |
| 3 | Case vs Visit | **Case فعلی همان واحد مشاوره است**؛ Visit جدا در v2 اگر لازم شد | کار تکراری نکنیم |
| 4 | Consent حداقل Pilot | `consent_to_store_data` موجود = PROFILE_RECORDING | ساده؛ جدول چندنوعی در Phase بعد |
| 5 | POS | fallback دستی / Sale موجود کافی است | اتصال کامل POS فعلاً سرعت را کم می‌کند |
| 6 | ویرایش Fact | فروشنده با Audit می‌تواند یادداشت/پاسخ جلسه را بزند؛ Fact دائمی ترجیحاً با تأیید مشتری (آینده) | گالری بدون اصطکاک |
| 7 | Retention | پیشنهاد ۲۴ ماه عدم مراجعه → Archive (سیاست؛ هنوز خودکار نیست) | انبار داده بی‌پایان نه |
| 8 | زبان UI | فارسی اولویت گالری | مشتری و فروشنده فارسی |

**قفل قرارداد توصیه (Qwen1):** خروجی پروفایل به موتور حداقل `{"concerns": ...}` است.
