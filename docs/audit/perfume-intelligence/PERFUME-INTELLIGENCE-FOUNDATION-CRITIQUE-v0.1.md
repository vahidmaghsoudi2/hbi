# Perfume Intelligence — Foundation Critique and Integration Direction v0.1

## Status

```text
Status: GOVERNANCE / AUDIT DIRECTION
Not a Reality Audit
Not Repository Evidence
Not Architecture Decision
Not Contract
Not Implementation Authorization
```

## Critical distinction

```text
Foundation = domain knowledge, hypotheses and risk controls
Reality Integration Audit = repository / test / CI / runtime evidence
Architecture Decision = Reuse / Extend / New based on evidence
Contract = approved behavior and data boundary
Implementation = authorized engineering work
```

## Architectural principle candidate

```text
One canonical product identity
```

Candidate only — not a claim that current HBI already has a specific Product Master ownership model. Requires verification.

## Directions (authorization boundaries)

```text
No parallel Product Master is authorized.
No parallel Evidence Engine is authorized.
No new ProductKnowledge / fragrance engine is authorized without verified gap.
```

New Master only after: Repository Evidence → Verified Requirement → Verified Gap → Reuse/Extend fitness → Architecture Justification → Governance → PO Approval.

Evidence and ProductKnowledge: audit existing capability first (cardinality, update semantics, provenance, conflict, identity link).

Lifecycle: any fragrance lifecycle is Domain Lifecycle Proposal only; must not replace HBI lifecycle without full evidence path + PO Approval.

## Claim and status separation

```text
Claim Type ≠ Evidence Status ≠ QA Status ≠ Confidence ≠ Conflict
```

Terms such as FACT, MANUFACTURER_CLAIM, OBSERVATION, CUSTOMER_REPORT, INFERENCE are Domain Taxonomy Candidates only — not confirmed HBI enums.

## Reality-audit rules

```text
Artifact Exists ≠ Capability Exists
Capability Exists ≠ Verified Behavior
Verified Behavior ≠ Accepted Architecture
PO Approval ≠ Repository Evidence
Documentation Verified ≠ Repository Behavior Verified
```

## Reuse / Extend / New protocol

```text
Evaluate Existing → Reuse Fitness → Extension Fitness → only if both fail → New
```

No New capability as solution before a verified gap exists.

## Deferred items

Similarity; numeric scoring; automatic ranking/recommendation/learning; candidate-count rule; performance normalization; New Master / Evidence / ProductKnowledge / Lifecycle engines.
