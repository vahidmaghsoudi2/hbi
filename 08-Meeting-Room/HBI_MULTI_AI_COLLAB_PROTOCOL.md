# HBI — Multi-AI Collaboration Protocol (Read-Only agents + Write Bridge)

**Goal:** Faster progress, less Grok token burn, zero PO message-passing.
**Status:** ACTIVE PILOT
**Date:** 2026-08-23

```text
Generated by Grok1, Reviewed by PO, Executed by Grok1
```

---

## Roles

| Role | Who | Can |
|------|-----|-----|
| **Commander** | PO | Strategy, final product decisions |
| **Gate / QA** | Qwen1 | Task SCOPE, EXECUTE_APPROVED, verdict |
| **Analyst / Author** | DeepSeek, Qwen2, Perplexity, etc. | READ GitHub, draft full file content, diff analysis |
| **Write Bridge** | Grok1 (or Grok2) | Single verified Write + Actions TRACE |
| **Fallback Write** | PO | `po-one-paste.ps1` if Bridge offline |

Read-only agents **never** claim Commit/Push succeeded.

---

## Token-saving pattern (recommended)

```text
Qwen1 → one TASK brief (SCOPE + DONE WHEN)
        ↓
DeepSeek/Qwen2 → READ GitHub themselves (raw URLs / their tools)
        ↓
Produce ONE Member Package (full file body, not chat essays)
        ↓
Grok1 → one batch Write (Change Package) + one TRACE
        ↓
DeepSeek/Qwen2 → READ result SHA/Actions themselves → VERIFIED report to Qwen1
```

**Grok should NOT** re-explain the whole codebase to them.
**They should NOT** ask Grok to “paste file contents” if they can raw-read GitHub.

---

## Member Package (mandatory for non-writers)

Use `agent-jobs/TEMPLATES/MEMBER_PACKAGE.txt`:

```text
TASK:
OWNER:
GITHUB_PATH:
COMMIT_MSG: (Generated by OWNER, Reviewed by Qwen1, Executed by Grok1|PO)
DONE_WHEN:
CONSTRAINTS:
-----BEGIN FILE-----
(full content)
-----END FILE-----
```

Multiple related files → one **Change Package** list (paths + bodies) for **one** Grok commit.

---

## How Grok spends tokens (minimize)

| Do | Don't |
|----|--------|
| Write only when package is complete | Debate design for pages |
| Batch related files in one `push_files` | One commit per typo discussion |
| Point others to raw.githubusercontent.com URLs | Re-dump entire files into chat |
| TRACE short | Re-litigate Framework text |
| Stop after VERIFY | Parallel speculative branches |

---

## How DeepSeek / Qwen (no Write) work

1. `git` reality via public raw URLs, e.g.  
   `https://raw.githubusercontent.com/vahidmaghsoudi2/hbi/master/<path>`
2. Analyze offline in their chat.
3. Output **only** Member Package / Change Package.
4. After Grok TRACE with SHA: open that SHA raw URL and confirm.
5. Report to Qwen1: `TASK / SHA / VERIFIED|FAIL / evidence links` — not novels.

---

## Escalation

- Incomplete package → Grok returns **REJECT — incomplete package** (no Write).
- False “already committed” by any agent → Reality Check; Framework 5 style reject.
- Bridge offline → PO `agent-jobs/po-one-paste.ps1` once.

---

## Success metric

One Gate/Task ≈ **one** Grok Write session ≈ **one** SHA ≈ **one** Actions run ≈ **one** TRACE.
Everyone else reads GitHub; PO is not the mailman.
