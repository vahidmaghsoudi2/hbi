## 📌 Overview

طراحی جامع پروفایل مشتری HBI از **۸ زاویه مختلف** برای استفاده در فرآیندهای فروش، مشاوره، خدمات پس از فروش و تحلیل کسب‌وکار.

---

## 🎭 دیدگاه‌های ۸ گانه

### 🤖 ۱. هوش مصنوعی (AI Agent)
**اطلاعات حیاتی:**
- Skin Profile (نوع پوست، مشکلات، آلرژی‌ها)
- Behavioral Pattern (الگوی خرید، تکرار بازدید)
- Evidence Integration (شواهد بالینی مرتبط)
- Recommendation History (توصیه‌های قبلی و نتایج)
- Contraindications (موارد منع مصرف)

**هدف:** توصیه‌های شخصی‌سازی‌شده و ایمن

### 👤 ۲. مشتری (Customer)
**اطلاعات مورد انتظار:**
- Goals (اهداف زیبایی و پوستی)
- Concerns (نگرانی‌های فعلی)
- Budget (بودجه ماهانه)
- Preferences (برندهای مورد علاقه، بافت، رایحه)
- Experience Level (سطح آشنایی با روتین‌ها)

**هدف:** دریافت مشاوره دقیق و محصولات مناسب

### 💼 ۳. فروشنده (Sales Consultant)
**اطلاعات عملیاتی:**
- Purchase History (تاریخچه خرید)
- Service History (خدمات دریافت‌شده)
- Product Preferences (رضایت از محصولات)
- Frequency (الگوی مراجعه)
- Upsell Opportunities (محصولات مکمل)

**هدف:** افزایش فروش و حفظ مشتری

### 👨‍⚕️ ۴. پزشک/متخصص (Dermatologist)
**اطلاعات پزشکی:**
- Medical History (بیماری‌ها، داروها)
- Allergies (آلرژی‌های دارویی و شیمیایی)
- Skin Assessment (ارزیابی تخصصی)
- Treatment History (درمان‌های قبلی)
- Contraindications (حاملگی، شیردهی، بیماری خاص)

**هدف:** درمان ایمن و جلوگیری از عوارض

### 🖥️ ۵. اپراتور سیستم (System Operator)
**اطلاعات فنی:**
- Data Quality (کامل بودن و صحت)
- Integration Status (اتصال با سیستم‌های دیگر)
- Privacy Compliance (GDPR)
- Audit Trail (تاریخچه تغییرات)
- Backup Status

**هدف:** یکپارچگی داده‌ها و امنیت

### 💰 ۶. حسابدار (Accountant)
**اطلاعات مالی:**
- Customer Lifetime Value (CLV)
- Revenue by Category
- Payment History
- Package Status
- Discount Usage

**هدف:** تحلیل سودآوری و گزارش‌گیری

### 📈 ۷. مدیر کسب‌وکار (Business Manager)
**اطلاعات استراتژیک:**
- Retention Rate
- Customer Segmentation (VIP, Regular, New, At-Risk)
- Churn Risk
- Satisfaction Score (NPS)
- Market Trends

**هدف:** تصمیم‌گیری استراتژیک

### 🔬 ۸. محقق (Researcher)
**اطلاعات تحلیلی:**
- Treatment Efficacy
- Product Performance
- Pattern Recognition
- A/B Testing Results
- Long-term Outcomes

**هدف:** بهبود محصولات و توصیه‌ها

## 🏗️ CustomerProfile Schema

```yaml
CustomerProfile:
  # === اطلاعات پایه ===
  personal_info:
    customer_id: UUID
    first_name: string
    last_name: string
    birth_date: date (optional)
    age_range: enum [teen, young_adult, adult, middle_age, senior]
    gender: enum [female, male, non_binary, prefer_not_to_say]
    contact:
      phone: string
      email: string
      preferred_contact: enum [phone, email, sms, whatsapp]

  # === ارزیابی پوست و مو ===
  skin_assessment:
    skin_type: enum [oily, dry, combination, sensitive, normal]
    fitzpatrick_scale: enum [I, II, III, IV, V, VI]
    concerns: array[string]
    sensitivity_level: enum [low, medium, high]
    hydration_level: number (0-100)
    ph_level: number (4.5-7.0)
    elasticity_score: number (0-100)

  hair_assessment:
    hair_type: enum [straight, wavy, curly, coily]
    hair_thickness: enum [fine, medium, thick]
    scalp_condition: enum [oily, dry, normal, sensitive, dandruff]
    concerns: array[string]

  # === اطلاعات پزشکی ===
  medical_history:
    allergies: array[string]
    medications: array[object]
      name: string
      dosage: string
      frequency: string
    medical_conditions: array[string]
    previous_treatments: array[object]
      treatment_type: string
      date: date
      outcome: enum [excellent, good, fair, poor, adverse_reaction]
    contraindications: array[string]

  # === روتین فعلی ===
  current_routine:
    morning:
      cleanser: string
      toner: string
      serum: array[string]
      moisturizer: string
      sunscreen: string (SPF level)
    evening:
      cleanser: string
      treatment: array[string]
      moisturizer: string
    weekly_treatments: array[string]

  # === اهداف و ترجیحات ===
  goals:
    primary_concerns: array[string] (max 3)
    timeline: enum [immediate, short_term, long_term]
    budget_range: enum [low, medium, high, premium]
    preferred_brands: array[string]
    avoided_ingredients: array[string]
    texture_preferences: enum [lightweight, rich, gel, cream, oil]

  # === تاریخچه تعامل ===
  interaction_history:
    first_visit: date
    total_visits: number
    average_spend: number
    purchase_history: array[PurchaseRecord]
    service_history: array[ServiceRecord]
    consultation_notes: array[object]
      date: date
      consultant: string
      notes: string
      recommendations: array[string]

  # === معیارهای کسب‌وکار ===
  business_metrics:
    customer_segment: enum [VIP, loyal, regular, new, at_risk, churned]
    lifetime_value: number
    retention_score: number (0-100)
    satisfaction_score: number (0-100)
    last_visit_date: date
    next_appointment: date (optional)

  # === متادیتای سیستم ===
  metadata:
    created_at: timestamp
    updated_at: timestamp
    data_completeness: number (0-100)
    consent_given: boolean
    consent_date: date
    privacy_policy_version: string
```

بله؛ پیشنهاد می‌کنم در HBI یک ماژول مستقل به نام **«پروفایل هوشمند مشتری و مشاوره»** ایجاد شود: فرم کوتاه، مرحله‌ای، رضایت‌محور و قابل‌ویرایش که فقط اطلاعات لازم برای فروش، توصیه محصول، پیگیری نتیجه و خدمات پس از فروش را دریافت کند. این بخش باید «کمک‌کننده به تصمیم انسان» باشد، نه جایگزین پزشک یا ابزار تشخیص بیماری.

اطلاعات پوست، مو، حساسیت‌ها و به‌ویژه عکس چهره می‌تواند در بسیاری از نظام‌های حریم خصوصی در دسته داده‌های حساس یا داده‌های سلامت قرار گیرد؛ بنابراین باید با رضایت صریح، هدف روشن، کمینه‌سازی داده و امکان حذف/ویرایش اداره شود.[1][2][3]

## چشم‌انداز ماژول

نام پیشنهادی:

```text
HBI Client Profile & Beauty Consultation
پروفایل مشتری، نیازسنجی و مشاوره هوشمند
```

هدف آن این نیست که از مشتری یک پرونده پیچیده بسازد. هدف این است که فروشنده یا اپراتور، در کمتر از ۲ تا ۴ دقیقه، اطلاعاتی بگیرد که به چهار سؤال پاسخ دهد:

1. این شخص **چه چیزی می‌خواهد**؟
2. پوست، مو و شرایط استفاده او چه محدودیت‌هایی دارد؟
3. چه محصولی قبلاً امتحان کرده و چه نتیجه‌ای گرفته است؟
4. کدام محصول موجود، قابل‌توضیح و کم‌ریسک برای او مناسب‌تر است؟

### خروجی مورد انتظار

پس از ثبت فرم، سیستم باید به اپراتور یک صفحه ساده بدهد:

```text
هدف مشتری: ضدآفتاب روزانه برای پوست حساس و مختلط
محدودیت مهم: سابقه سوزش با محصولات عطری
روتین فعلی: شوینده + مرطوب‌کننده؛ ضدآفتاب نامنظم
محصولات قابل بررسی: فقط موجود، VERIFIED و بدون Conflict بحرانی
پیشنهاد فروشنده: 2 گزینه اولویت‌دار + دلیل + روش مصرف
هشدار: در صورت سابقه واکنش شدید، بیماری پوستی فعال یا درمان دارویی، ارجاع به پزشک/داروساز
پیگیری: 7 تا 14 روز پس از خرید
```

## اطلاعات لازم از مشتری

### 1. هویت و ارتباطات

این بخش باید حداقلی باشد و برای ایجاد پرونده، خرید و پیگیری استفاده شود.

| داده | الزامی؟ | کاربرد |
|---|---:|---|
| نام و نام خانوادگی | اختیاری یا حداقل نام | خطاب محترمانه و تشخیص مشتری تکراری |
| شماره موبایل | اختیاری، با رضایت | پیگیری خرید، اطلاع‌رسانی و خدمات پس از فروش |
| کانال ارتباطی ترجیحی | اختیاری | تماس، پیامک، واتساپ/تلگرام در صورت مجاز بودن |
| تاریخ تولد کامل | بهتر است خیر | به‌جای آن بازه سنی دریافت شود |
| بازه سنی | اختیاری | انتخاب روتین و زبان مشاوره مناسب |
| شهر یا منطقه آب‌وهوایی | اختیاری | اقلیم، آفتاب، خشکی، رطوبت و سبک زندگی |
| رضایت برای پیگیری | الزامی برای تماس بعدی | جلوگیری از پیام ناخواسته |

**پیشنهاد:** به جای تاریخ تولد، از بازه‌های «زیر 18، 18–24، 25–34، 35–44، 45–54، 55+» استفاده شود؛ برای بیشتر توصیه‌های فروش، این مقدار کافی‌تر و کم‌خطرتر است.

### 2. هدف مراجعه و اولویت خرید

این قسمت باید در ابتدای فرم باشد؛ چون مسیر پرسش‌ها را تعیین می‌کند.

```text
امروز برای چه چیزی آمده‌اید؟
[ ] ضدآفتاب
[ ] پاک‌کننده و شوینده
[ ] مرطوب‌کننده
[ ] آبرسان / سرم
[ ] ضدلک و روشن‌کننده
[ ] ضدجوش
[ ] ضدچروک / مراقبت از سن
[ ] مراقبت پوست حساس
[ ] مراقبت مو و پوست سر
[ ] آرایش
[ ] محصول کودک
[ ] هدیه
[ ] تعویض یا پیگیری خرید قبلی
[ ] سایر
```

سپس:

```text
اولویت اصلی شما چیست؟
[ ] کیفیت و نتیجه
[ ] سازگاری با پوست حساس
[ ] بافت سبک و جذب سریع
[ ] رنگی بودن / پوشانندگی
[ ] بی‌رنگ بودن
[ ] قیمت اقتصادی
[ ] برند مشخص
[ ] ترکیبات مشخص
[ ] محصول موجود برای خرید فوری
```

این اطلاعات برای فروشنده، موتور توصیه، انبار و بخش خدمات پس از فروش بسیار ارزشمند است.

### 3. پروفایل پوست

این بخش باید خوداظهاری باشد؛ یعنی سیستم ننویسد «تشخیص پوست شما فلان است»، بلکه بپرسد «شما معمولاً چه تجربه‌ای دارید؟»

| پرسش | گزینه‌های پیشنهادی | کاربرد |
|---|---|---|
| نوع کلی پوست | خشک، چرب، مختلط، نرمال، مطمئن نیستم | انتخاب بافت و روتین |
| وضعیت فعلی پوست | متعادل، کم‌آب، براق، پوسته‌پوسته، تحریک‌شده، نامشخص | تعیین نیاز فوری |
| حساسیت ادراک‌شده | ندارد، کم، متوسط، زیاد، مطمئن نیستم | پرچم احتیاط |
| نگرانی اصلی | جوش، لک، تیرگی، قرمزی، خشکی، خطوط، منافذ، کدری، آفتاب | هدف‌گذاری محصول |
| واکنش به محصول جدید | معمولاً خیر، گاهی، اغلب، سابقه واکنش شدید | تعیین نیاز به Patch Test یا ارجاع |
| ناحیه مصرف | صورت، دورچشم، بدن، لب، دست، گردن، پوست سر | محدودسازی پیشنهاد |
| میزان قرارگیری در آفتاب | کم، متوسط، زیاد، شغلی/فضای باز | اولویت ضدآفتاب و تمدید |
| استفاده از آرایش | هرگز، گاهی، روزانه | سازگاری با ضدآفتاب/بافت/رنگ |
| ترجیح ظاهری | رنگی، بی‌رنگ، پوشانندگی کم، متوسط، زیاد | انتخاب Variant مناسب |

### 4. پروفایل مو و پوست سر

برای گالری آرایشی و بهداشتی، مو و پوست سر باید جدا از پوست صورت ثبت شود.

| پرسش | گزینه‌های پیشنهادی | کاربرد |
|---|---|---|
| جنس مو | صاف، موج‌دار، فر، خیلی فر، نامشخص | بافت و روش مصرف |
| ضخامت تار مو | نازک، متوسط، ضخیم، نامشخص | انتخاب شامپو/ماسک/سرم |
| وضعیت ریشه | چرب، خشک، متعادل، حساس | انتخاب محصول پوست سر |
| وضعیت ساقه مو | خشک، آسیب‌دیده، رنگ‌شده، دکلره، شکننده، معمولی | مراقبت ترمیمی |
| نگرانی اصلی | ریزش، شوره، خارش، خشکی، وز، موخوره، کدری، آسیب حرارتی | مسیر مشاوره |
| دفعات شست‌وشو | روزانه، یک‌روزدرمیان، 2–3 بار در هفته، کمتر | طراحی روتین |
| رنگ/دکلره/کراتین/فر | بله/خیر + زمان تقریبی | ریسک ناسازگاری و انتخاب محصول |
| ابزار حرارتی | هرگز، گاهی، مکرر | نیاز به محافظت حرارتی |

**مرز مهم:** «ریزش ناگهانی یا شدید مو»، «زخم/عفونت پوست سر»، «خارش شدید و مداوم» یا «التهاب فعال» نباید با توصیه فروشگاهی حل شود؛ سیستم باید اپراتور را به مسیر ارجاع به پزشک یا داروساز هدایت کند.

### 5. روتین فعلی و سابقه محصول

این بخش یکی از مهم‌ترین منابع داده برای فروش واقعی و خدمات پس از فروش است.

```text
اکنون چه محصولاتی استفاده می‌کنید؟
- شوینده:
- مرطوب‌کننده:
- ضدآفتاب:
- سرم/درمان:
- شامپو:
- ماسک/نرم‌کننده:
- آرایش روزانه:
```

اما بهتر است فرم مشتری را مجبور به تایپ طولانی نکند:

| داده | نمونه پاسخ | کاربرد |
|---|---|---|
| برند/نام محصول فعلی | «ضدآفتاب X» | یافتن تکرار، جایگزین یا ناسازگاری |
| مدت استفاده | تازه، کمتر از 1 ماه، 1–6 ماه، بیش از 6 ماه | تحلیل اثر و رضایت |
| نتیجه | راضی، متوسط، ناراضی | جلوگیری از تکرار تجربه ناموفق |
| علت نارضایتی | سوزش، جوش، چربی، سفیدک، قیمت، بی‌اثر بودن، بو، پوشانندگی | شخصی‌سازی فروش |
| محصول محبوب قبلی | نام یا نوع محصول | کشف preference |
| محصولی که واکنش داده | نام/برند در صورت یادآوری | پرچم احتیاط |

سیستم باید سابقه خرید HBI را خودکار به این پروفایل اضافه کند، نه اینکه هر بار از مشتری بپرسد. مشتری فقط باید امکان **تأیید، اصلاح یا رد** آن سابقه را داشته باشد.

### 6. اطلاعات ایمنی و ارجاع

این بخش باید کوتاه، اختیاری، رضایت‌محور و با زبان غیرپزشکی باشد. هدف آن تشخیص بیماری نیست؛ فقط جلوگیری از توصیه نامناسب است.

```text
آیا موردی هست که برای پیشنهاد محصول باید بدانیم؟
[ ] پوست بسیار حساس یا سابقه حساسیت
[ ] واکنش یا آلرژی شناخته‌شده به عطر، نگهدارنده یا ماده خاص
[ ] استفاده از درمان پوستی تجویزی یا داروی موضعی
[ ] بارداری یا شیردهی (فقط در صورت تمایل)
[ ] بیماری یا التهاب پوستی فعال
[ ] هیچ‌کدام
[ ] ترجیح می‌دهم پاسخ ندهم
```

### قواعد سیستم برای ایمنی

| وضعیت | واکنش سیستم |
|---|---|
| سابقه واکنش شدید یا آلرژی | محصول جدید به‌عنوان «نیازمند بررسی انسانی» علامت‌گذاری شود |
| التهاب شدید، زخم، عفونت یا مشکل حاد | توقف توصیه خودکار و پیشنهاد مراجعه به پزشک/داروساز |
| استفاده از درمان پوستی تجویزی | هشدار به فروشنده و عدم ارائه ادعای درمانی |
| پوست حساس یا روزاسه خوداظهاری‌شده | پیشنهاد با احتیاط، ثبت Patch Test و اجتناب از ادعای قطعی |
| محصول جدید | پیشنهاد Patch Test پیش از مصرف گسترده |

راهنمای آکادمی پوست آمریکا نیز توصیه می‌کند پیش از افزودن محصول مراقبتی جدید، آن را روی ناحیه کوچکی از پوست روزی دو بار طی 7 تا 10 روز آزمایش کنید؛ این توصیه باید در بخش «روش استفاده ایمن» سیستم گنجانده شود.[4]

## نگاه نقش‌های مختلف

| نقش | چه اطلاعاتی نیاز دارد؟ | خروجی مطلوب |
|---|---|---|
| مشتری | هدف، بودجه، ترجیح بافت/رنگ، تجربه قبلی، رضایت | تجربه سریع، بدون پرسش اضافی، پیشنهاد قابل فهم |
| فروشنده | نیاز اصلی، حساسیت، موجودی، سابقه خرید، دلیل پیشنهاد | فروش مستدل و بدون فشار |
| مشاور زیبایی | نوع پوست/مو، روتین، نگرانی‌ها، واکنش‌های قبلی | روتین ساده و مرحله‌ای |
| پزشک/داروساز | علائم هشدار، درمان‌های در حال مصرف، واکنش شدید | ارجاع مناسب؛ بدون تشخیص در گالری |
| اپراتور | فرم کوتاه، انتخاب‌های آماده، هشدارهای واضح | ثبت سریع و خطای کمتر |
| حسابدار | تاریخچه خرید، تعداد، مبلغ، بازگشت/مرجوعی، وفاداری | تحلیل فروش و بازگشت مشتری |
| مدیر انبار | تقاضای ثبت‌شده، دلیل عدم خرید، درخواست محصول ناموجود | پیش‌بینی تأمین کالا |
| مدیر کسب‌وکار | دسته‌بندی نیاز، نرخ تبدیل مشاوره به خرید، رضایت | تصمیم‌گیری مبتنی بر داده |
| هوش مصنوعی HBI | داده حداقلی، Evidence محصول، موجودی، Conflict/Unknown | توصیه شفاف، قابل ردگیری و امن |

## تجربه کاربری پیشنهادی

فرم طولانی در ابتدای ورود مشتری، نرخ تکمیل را پایین می‌آورد. راه بهتر یک فرایند چهارمرحله‌ای است.

### مرحله اول: شروع سریع — 30 ثانیه

```text
برای چه چیزی مراجعه کرده‌اید؟
پوست شما معمولاً چگونه است؟
آیا پوست/پوست سر حساس دارید؟
رنگی می‌خواهید یا بی‌رنگ؟
```

### مرحله دوم: نیاز دقیق — 60 تا 90 ثانیه

فقط بر اساس انتخاب مرحله اول سؤال‌های مرتبط نمایش داده شود. مثلاً برای ضدآفتاب:

```text
میزان حضور در آفتاب؟
نوع بافت دلخواه؟
آرایش می‌کنید؟
سابقه سوزش یا جوش با ضدآفتاب داشته‌اید؟
```

### مرحله سوم: روتین و سابقه

```text
چه چیزی اکنون استفاده می‌کنید؟
از آن راضی هستید؟
چه مشکلی می‌خواهید حل شود؟
```

### مرحله چهارم: رضایت و پیگیری

```text
اجازه می‌دهید برای پیگیری نتیجه خرید با شما تماس بگیریم؟
[ ] فقط فاکتور و سابقه خرید
[ ] یادآوری زمان مصرف/تمدید
[ ] پیگیری رضایت 7 تا 14 روز بعد
[ ] پیشنهادهای آینده
[ ] هیچ‌کدام
```

## نسخه حداقلی قابل‌اجرا

برای شروع کدنویسی، پیشنهاد من این است که Home Page فقط این هشت بخش را داشته باشد:

```text
1. شماره موبایل یا جست‌وجوی مشتری
2. نام مشتری
3. هدف مراجعه
4. نوع پوست
5. نگرانی اصلی
6. حساسیت / سابقه واکنش
7. رنگی یا بی‌رنگ بودن
8. رضایت برای ثبت و پیگیری
```

و سپس در صفحه مشاوره:

```text
- روتین فعلی
- پیشنهادهای موجود و VERIFIED
- علت پیشنهاد
- هشدارها / محدودیت‌ها
- نتیجه فروش
- زمان پیگیری
```

این نسخه به‌قدر کافی ساده است که اپراتور واقعاً از آن استفاده کند، و به‌قدر کافی کامل است که موتور توصیه HBI داده مفید داشته باشد.

### اصل «داده از منبع»

هر داده باید مشخص کند از کجا آمده است:

```text
source = CUSTOMER_SELF_REPORT | SALES_OPERATOR | PURCHASE_HISTORY | CONSENTED_PHOTO | VERIFIED_PRODUCT_DATA
recorded_at = timestamp
confirmed_by_customer = true / false
confidence = self_reported / system_derived / verified
```

این اصل با Frameworkهای فعلی HBI سازگار است: سیستم نباید حدس خود را به «Fact» تبدیل کند. مثلاً «پوست چرب» باید با برچسب `CUSTOMER_SELF_REPORT` ثبت شود، نه تشخیص قطعی.

## حریم خصوصی و کنترل مشتری

برای این ماژول، این پنج قاعده باید غیرقابل‌چشم‌پوشی باشند:

1. **رضایت جداگانه:** رضایت برای ایجاد پرونده با رضایت برای پیام تبلیغاتی یکی نیست.
2. **کمینه‌سازی داده:** فقط داده‌ای گرفته شود که برای مشاوره، فروش یا پیگیری هدف مشخص لازم است. اصل Data Minimisation می‌گوید داده باید کافی، مرتبط و محدود به میزان ضروری باشد.[2]
3. **حق اصلاح و حذف:** مشتری بتواند اطلاعات خود را ببیند، تصحیح کند و در حدود قانون درخواست حذف بدهد.
4. **عدم نیاز به عکس در نسخه اول:** عکس چهره یا پوست فقط در نسخه پیشرفته و با رضایت صریح گرفته شود؛ تا آن زمان اختیاری و خاموش باشد.
5. **عدم تشخیص پزشکی:** HBI توصیه فروشگاهی و آموزشی می‌دهد، نه تشخیص یا درمان. داده‌های سلامت و پروفایل‌سازی مبتنی بر آن‌ها حساس‌اند و ممکن است نیازمند رضایت صریح باشند.[1][5]

🧠 طراحی سیستم جمع‌آوری اطلاعات مشتری برای گالری آرایشی و بهداشتی

این پروژه یک سیستم اطلاعات مشتری (CIS)  است که برای گالری‌های آرایشی و بهداشتی طراحی شده. هدف اصلی این است که با جمع‌آوری اطلاعات درست و هدفمند، تجربه مشتری را شخصی‌سازی کنیم، فروش را افزایش دهیم و خدمات پس از فروش را حرفه‌ای‌تر کنیم.

برای طراحی این سیستم، از زاویه‌های مختلف به موضوع نگاه کردم تا مطمئن شوم همه نیازها را پوشش می‌دهد. در ادامه، از منظر هر نقش، اطلاعات کلیدی و کاربرد آن توضیح داده شده:

---

۱. 🤖 از نگاه هوش مصنوعی (سیستم / طراح)

سیستم باید طوری طراحی شود که:

· ساده: کار با آن برای فروشنده و مشتری آسان باشد.
· کامل: همه اطلاعات مورد نیاز برای فروش و خدمات را داشته باشد.
· مدرن: از فرم‌های هوشمند استفاده کند که بر اساس پاسخ مشتری، سوالات بعدی را تغییر می‌دهد.
· قابل اتصال: با سیستم‌های مدیریت مشتری (CRM) و فروش هماهنگ باشد.

نکته مهم: اطلاعات باید در یک ساختار منظم ذخیره شوند تا به راحتی قابل جستجو، تحلیل و استفاده باشند.

---

۲. 🧑‍🦰 از نگاه مشتری (خریدار)

مشتری دوست دارد:

· سریع ثبت‌نام شود.
· حس کند که منحصر به فرد است و خدمات برایش شخصی‌سازی می‌شود.
· حریم خصوصی اش حفظ شود.

اطلاعاتی که مشتری راحت ارائه می‌دهد:

دسته اطلاعات نمونه فیلدها
هویت نام، نام خانوادگی، تاریخ تولد (برای هدیه تولد)، جنسیت
ارتباط شماره موبایل، ایمیل (برای اطلاع‌رسانی)
علایق اولیه دوست دارد چه محصولاتی (ضدآکنه، ضدچروک، آرایشی) بخرد یا چه خدماتی دریافت کند.

---

۳. 🛍️ از نگاه فروشنده (مشاور فروش)

فروشنده برای فروش موفق و مشاوره دقیق به این اطلاعات نیاز دارد:

دسته اطلاعات نمونه فیلدها چرا مهم است؟
پروفایل پوست و مو نوع پوست (چرب، خشک، مختلط، حساس), وضعیت مو (چرب، خشک، رنگ‌شده), نگرانی‌های اصلی (جوش، لک، چین و چروک، ریزش مو) برای پیشنهاد محصول و خدمات مناسب.
سبک زندگی میزان خواب، سطح استرس، رژیم غذایی، مصرف سیگار و الکل این عوامل مستقیماً روی پوست و مو تأثیر می‌گذارند.
سابقه خرید و رفتار محصولات و برندهای قبلی, میزان بودجه, انگیزه خرید (هدیه، استفاده شخصی) برای فروش مکمل و پیشنهاد محصولات مرتبط.
ترجیحات ارتباطی روش ارتباط ترجیحی (پیامک، واتساپ، ایمیل) برای خدمات پس از فروش مؤثر.

اطلاعاتی مانند وضعیت پوست، نگرانی‌ها و عادات خرید معمولاً فقط در گفتگوی رو در رو قابل کشف هستند و سیستم باید ثبت آن‌ها را آسان کند.

---

۴. 👩‍⚕️ از نگاه پزشک / متخصص پوست و زیبایی

برای هر درمان یا استفاده از محصولات تخصصی، اطلاعات پزشکی حیاتی است:

دسته اطلاعات نمونه فیلدها چرا مهم است؟
سابقه پزشکی بیماری‌های زمینه‌ای (دیابت، فشار خون، مشکلات تیروئید), سابقه حساسیت‌های پوستی شدید برای جلوگیری از عوارض درمان.
داروهای مصرفی قرص‌های ضدبارداری، داروهای هورمونی، روتاکیوتان برخی داروها با درمان‌های زیبایی تداخل دارند.
بارداری / شیردهی وضعیت بارداری یا شیردهی بسیاری از درمان‌ها و محصولات در این دوران ممنوع هستند.

این اطلاعات بسیار حساس هستند و باید با رعایت کامل حریم خصوصی و با کسب رضایت آگاهانه مشتری ذخیره شوند.

---

۵. 📊 از نگاه مدیر / صاحب فروشگاه

مدیریت برای بهینه‌سازی کسب‌وکار به داده‌های کلان نیاز دارد:

دسته اطلاعات نمونه فیلدها کاربرد مدیریتی
دموگرافیک سن، جنسیت، منطقه سکونت، شغل تحلیل بازار هدف و تصمیم‌گیری برای خرید محصول.
ارزش مشتری میزان خرید کل، تعداد دفعات مراجعه، میانگین خرید هر بار شناسایی مشتریان وفادار و ارزشمند.
منبع جذب از کجا به فروشگاه آمده (اینستاگرام، دوستان، تبلیغات) بهینه‌سازی هزینه‌های بازاریابی.
بازخورد و شکایت ثبت نظرات، پیشنهادات و شکایات مشتریان بهبود مستمر کیفیت خدمات و محصولات.

---

۶. 💰 از نگاه حسابدار / امور مالی

· اطلاعات صورتحساب: نام و نام خانوادگی، آدرس (برای فاکتور), شماره اقتصادی/شناسه ملی (در صورت نیاز).
· سابقه پرداخت: روش پرداخت ترجیحی (نقد، کارت، اعتباری), سابقه خریدهای اقساطی.

---

🧩 جمع‌بندی نهایی: یک فرم جامع و مدرن

بر اساس همه این دیدگاه‌ها، بهترین کار این است که اطلاعات را در چهار بخش اصلی دسته‌بندی کنیم:

1. بخش اول: اطلاعات پایه و ارتباطی (برای همه مشتریان)
   · نام، نام خانوادگی، تاریخ تولد، جنسیت
   · شماره موبایل، ایمیل، آدرس (اختیاری)
2. بخش دوم: پروفایل زیبایی و سبک زندگی (برای مشاوره و فروش)
   · پوست: نوع پوست، نگرانی‌های اصلی، حساسیت‌ها و آلرژی‌ها
   · مو: نوع مو، وضعیت آن (خشک، چرب، رنگ‌شده)
   · سبک زندگی: میزان خواب، سطح استرس، رژیم غذایی
   · هدف: مشتری به دنبال چه نتیجه‌ای است؟ (مثلاً کاهش جوش، روشن‌تر شدن پوست)
3. بخش سوم: سابقه خرید و خدمات (برای CRM و فروش بیشتر)
   · تاریخ و نوع خدمات دریافت‌شده (فیشیال، ماساژ، کاشت مژه)
   · محصولات خریداری‌شده (نام، برند، تاریخ خرید)
   · بازخورد مشتری از هر بار خرید یا خدمات
4. بخش چهارم: اطلاعات حساس پزشکی (با رضایت آگاهانه)
   · بیماری‌های زمینه‌ای، داروهای مصرفی، بارداری/شیردهی، سابقه حساسیت‌های شدید

با داشتن این اطلاعات در یک سیستم، شما نه تنها یک فروشگاه، بلکه یک مرکز تخصصی زیبایی خواهید بود که خدماتش را دقیقاً بر اساس نیاز هر فرد تنظیم می‌کند. این یعنی مشتری راضی‌تر، فروش بیشتر و بازگشت مشتریان وفادار.






بله. این موضوع به‌نظر من باید قبل از Product Recommendation در HBI به‌عنوان یک لایه مستقل طراحی شود:
Customer Intelligence / پرونده هوشمند مشتری.

من چند منبع به‌روز حوزه مدیریت مشتری در سالن/Beauty و حریم خصوصی را هم بررسی کردم. یک نکته مشترک بسیار مهم دارند: پرونده مشتری نباید تبدیل به «فرم طولانی برای جمع‌کردن هر اطلاعات ممکن» شود؛ هر داده باید دلیل مشخصی برای جمع‌آوری داشته باشد و دسترسی به داده‌ها نیز بر اساس نقش باشد. 

1. اول یک تغییر نگرش مهم

اگر از دید HBI نگاه کنیم، سؤال نباید این باشد:

«از مشتری چه اطلاعاتی بگیریم؟»

بلکه:

«برای اینکه HBI بتواند در طول رابطه با مشتری تصمیم بهتری بگیرد، چه چیزهایی باید درباره او بداند؟»

و این تفاوت خیلی بزرگی است.

من اطلاعات مشتری را به ۸ لایه تقسیم می‌کنم:

لایه	چیزی که HBI باید بداند	کاربرد
1. Identity	چه کسی است؟	شناسایی
2. Relationship	رابطه‌اش با گالری چیست؟	CRM
3. Needs	چه می‌خواهد؟	مشاوره
4. Skin/Hair Profile	وضعیت پوست و مو چگونه است؟	Recommendation
5. Routine	اکنون چه می‌کند؟	تشخیص شکاف
6. History	قبلاً چه کرده و چه نتیجه‌ای گرفته؟	جلوگیری از تکرار خطا
7. Preferences	چه چیزهایی برایش مهم است؟	فروش/تجربه مشتری
8. Outcome	توصیه ما چه نتیجه‌ای داد؟	یادگیری HBI

این ساختار خیلی قدرتمندتر از یک «Customer Form» معمولی است.

5. اگر من «پزشک/متخصص» باشم

اینجا باید یک مرز معماری خیلی مهم ایجاد کنیم.

HBI نباید از اطلاعات مشتری نتیجه‌گیری پزشکی قطعی کند.

اما می‌تواند اطلاعات مرتبط را ثبت و Flag کند.

مثلاً:

* حساسیت گزارش‌شده
* سابقه واکنش به محصول
* بارداری/شیردهی، فقط اگر برای خدمت یا محصول مربوطه واقعاً لازم باشد
* داروها یا درمان‌های مرتبط، فقط در صورت ضرورت
* سابقه اقدامات زیبایی
* سابقه تحریک پوستی
* Patch Test
* contraindication ثبت‌شده توسط متخصص

و سپس:

REVIEW REQUIRED

نه:

«این فرد فلان بیماری را دارد.»

این تفاوت برای HBI حیاتی است.

اطلاعات سلامت و حساسیت‌ها حفاظت بیشتری می‌خواهند و منابع تخصصی مدیریت مشتری در Beauty نیز بر همین موضوع تأکید دارند.

پیشنهاد من برای گام بعد

من فعلاً کدنویسی یا تغییر Schema را شروع نمی‌کنم؛ چون هنوز باید یک تصمیم معماری بگیریم.

گام بعدی باید این باشد که همین ایده را تبدیل کنیم به یک HBI CUSTOMER INTAKE MATRIX؛ یعنی تک‌تک فیلدهای احتمالی را در جدول قرار دهیم و برای هرکدام مشخص کنیم:

Field → Purpose → Who asks → Source → Required/Optional → Privacy level → Who can see → HBI usage → When collected → Update frequency

بعد از آن می‌توانیم با خیال راحت تصمیم بگیریم که Customer Schema v1 دقیقاً چه چیزهایی داشته باشد و چه چیزهایی عمداً نداشته باشد.
